## 3. 障害①：Windowsのブラウザから表示できない（ファイアウォール）

### 症状
- ブラウザで `http://192.168.56.11` → **ERR_CONNECTION_TIMED_OUT**（応答時間が長すぎます）

### 切り分け
| 確認 | 結果 | 分かること |
|---|---|---|
| サーバ内から curl | 応答あり | Apacheは正常 |
| WindowsからSSH(22) | 接続可 | ネットワークは正常 |
| WindowsからHTTP(80) | タイムアウト | 80番だけ外から届いていない |

### 原因と対処
```
sudo firewall-cmd --list-all             # services: cockpit dhcpv6-client ssh（httpなし）
sudo firewall-cmd --permanent --add-service=http
sudo firewall-cmd --reload
sudo firewall-cmd --list-all             # services: cockpit dhcpv6-client http ssh
```
- `--permanent`：再起動後も残す / `--reload`：反映
- 結果：テストページが表示された

## 4. コンテンツ公開とログ確認
```
echo "<h1>mw01 Apache test by Kaito</h1>" | sudo tee /var/www/html/index.html
curl -I http://localhost                 # HTTP/1.1 200 OK / Content-Length: 35
```
- `sudo echo ... > ファイル` はリダイレクトにsudoが効かず Permission denied → `sudo tee` を使う

### access_log（何が起きたか）
```
sudo tail -n 5 /var/log/httpd/access_log
192.168.56.1 - - [28/Oct/2026:12:20:25 +0900] "GET / HTTP/1.1" 200 35 "-" "Mozilla/5.0 (Windows NT 10.0; ...) Chrome/..."
```
| 項目 | 値 |
|---|---|
| 接続元 | 192.168.56.1（Windows） |
| 要求 | GET / |
| 結果 | 200 / 35バイト |
| User-Agent | Chrome |

- `408`：Chromeの先回り接続（要求なしでタイムアウト）。問題なし
- `::1` からの `HEAD`：サーバ内の `curl -I`
- **ファイアウォールで止まっていた時間帯のアクセスはログに残っていない**
  → access_logに記録がなければApacheより手前（FW・NW）を疑う

### error_log（なぜ起きたか）
```
[autoindex:error] [client 192.168.56.1] AH01276: Cannot serve directory /var/www/html/: No matching DirectoryIndex (index.html) found
```
- 403の理由がそのまま記録されていた（index.html作成後は出なくなった）

## 5. 設定変更（ServerName追加）

### 目的
起動時の警告を解消する
```
AH00558: httpd: Could not reliably determine the server's fully qualified domain name ...
Set the 'ServerName' directive globally to suppress this message
```

### 手順（本番作業と同じ型）
```
# 1. バックアップ（-pで日時・権限を保持）
sudo cp -p /etc/httpd/conf/httpd.conf /etc/httpd/conf/httpd.conf.bak_20261028

# 2. 編集（vi: /^#ServerName → o → ServerName mw01:80 → Esc → :wq）
sudo vi /etc/httpd/conf/httpd.conf

# 3. 差分確認
diff /etc/httpd/conf/httpd.conf.bak_20261028 /etc/httpd/conf/httpd.conf
#   100a101
#   > ServerName mw01:80

# 4. 構文チェック
sudo apachectl configtest                # Syntax OK

# 5. 反映
sudo systemctl reload httpd

# 6. 確認
journalctl -u httpd --no-pager | tail -n 5   # AH00558 が出なくなった
```
- reload：PIDが変わらない（2498のまま）＝プロセスを止めずに設定を読み直す
- restart：PIDが変わる（2498 → 3240）＝プロセスを作り直す

## 6. 障害②：構文チェックをせずにrestartして停止（再現）

### 再現手順
```
sudo sed -i 's/^ServerName mw01:80/ServerNmae mw01:80/' /etc/httpd/conf/httpd.conf
grep -n "ServerN" /etc/httpd/conf/httpd.conf   # 101:ServerNmae mw01:80
sudo systemctl restart httpd
```
※ 1回目はsedの置換後の文字を打ち間違え、変更されていなかった。
  grepで「意図した変更になっていない」と気づける → 確認してから次へ進むのが鉄則

### 症状
```
Job for httpd.service failed because the control process exited with error code.
```
| status | 内容 |
|---|---|
| 先頭 | 赤い × |
| Active | failed (Result: exit-code) |
| Main PID | code=exited, status=1/FAILURE |

```
AH00526: Syntax error on line 101 of /etc/httpd/conf/httpd.conf:
Invalid command 'ServerNmae', perhaps misspelled or defined by a module not included in the server configuration
```
→ ファイル名・行番号・原因まで表示される

### ブラウザのエラーの違い
| | 障害①（FW） | 障害②（httpd停止） |
|---|---|---|
| エラー | ERR_CONNECTION_TIMED_OUT | ERR_CONNECTION_REFUSED |
| 意味 | パケットが黙って捨てられ返事がない | サーバに届いたが80番で待つプロセスがなく、即座に拒否 |
| 疑う場所 | サーバより手前（FW・NW） | サーバ内（サービス停止） |

### 復旧
```
sudo apachectl configtest                # 同じ構文エラーを確認
sudo sed -i 's/^ServerNmae mw01:80/ServerName mw01:80/' /etc/httpd/conf/httpd.conf
grep -n "ServerN" /etc/httpd/conf/httpd.conf
sudo apachectl configtest                # Syntax OK
sudo systemctl start httpd
systemctl status httpd --no-pager        # active (running)
```
- ブラウザで表示復旧を確認

### 気づき
- 起動失敗時の構文エラーは **error_log には記録されない**（ログを開く前に失敗するため）
  → 起動失敗は `journalctl -u httpd` / `systemctl status` で見る

## 面談で話す用まとめ
> 自宅の検証環境でApacheを構築し、外部から接続できない障害を「サーバ内→SSH→HTTP」の順に切り分けて、firewalldでhttpが許可されていないことを特定・解消しました。
> 設定変更は、バックアップ・diffでの差分確認・apachectl configtestでの構文チェック・reloadでの反映・ログでの確認という手順で行いました。
> また、構文チェックを省略してrestartした場合にhttpdが起動失敗する障害を再現し、journalctlのエラーメッセージから行番号と原因を特定して復旧しました。
> ブラウザのエラーがTIMED_OUTかREFUSEDかで、ファイアウォールの問題かサービス停止かを見分けられることも確認しています。
