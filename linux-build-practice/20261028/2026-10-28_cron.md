## 1. cron の基本

- `crond` サービスが、登録された時刻にコマンドを実行する
- 書式：`分 時 日 月 曜日 コマンド`

| 書き方 | 意味 |
|---|---|
| `* * * * *` | 毎分 |
| `*/5 * * * *` | 5分ごと |
| `0 3 * * *` | 毎日3:00 |
| `30 9 * * 1-5` | 平日9:30 |

| コマンド | 内容 |
|---|---|
| `crontab -e` | 編集（vi が開く） |
| `crontab -l` | 登録内容の表示 |
| `/var/spool/cron/<ユーザー名>` | 実際の保存先（ユーザーごと） |
| `/var/log/cron` | 実行ログ |

### vi の最低限の操作
| キー | 動作 |
|---|---|
| `i` | 入力モード |
| `Esc` | 入力モード終了 |
| `:wq` | 保存して終了 |
| `:q!` | 保存せずに終了 |
| `dd` | 1行削除 |
| `j` | 1行下へ移動 |

## 2. 毎分実行ジョブで動作確認

```
* * * * * date >> /home/kaito/cron_test.log
```

3つの方向から確認：
| 確認方法 | 結果 |
|---|---|
| 出力ファイル `cat /home/kaito/cron_test.log` | 毎分1行ずつ時刻が追記されていた |
| 実行ログ `sudo tail /var/log/cron` | 毎分 `CMD`（開始）→ `CMDEND`（終了） |
| 保存先 `sudo cat /var/spool/cron/kaito` | crontab -e の内容がそのまま保存 |

- ログ中の `anacron: Job 'cron.daily' started` は OS の日次処理。
  anacron は常時起動していないマシンでも、実行できなかった日次処理を起動後に実行する

## 3. わざと失敗させる（権限エラー）

```
*/5 * * * * df -h / >> /home/kaito/df.log 2>&1
* * * * * date >> /var/log/cron_test.log     ← 失敗させるジョブ
```

### 結果
```
CROND: (kaito) CMD (date >> /var/log/cron_test.log)
CROND: (kaito) CMDOUT (/bin/sh: line 1: /var/log/cron_test.log: Permission denied)
CROND: (kaito) CMDEND (date >> /var/log/cron_test.log)
```
```
$ ls -l /var/log/cron_test.log
ls: cannot access '/var/log/cron_test.log': No such file or directory
$ ls -ld /var/log
drwxr-xr-x. 7 root root 4096 Oct 27 11:30 /var/log
```

### 分かったこと
- `/var/log` は所有者 root のみ書き込み可（その他ユーザーは r-x）→ kaito は書けない
- **CMDEND は「終了した」であって「成功した」ではない**
- crontab に登録され、ログ上も毎分「実行・終了」しているのに、実際は一度も成功していない
  → 現場の「バッチは動いているはずなのにデータができていない」障害と同じパターン
- 今回は CMDOUT にエラーが出たが、メール送信設定があるサーバではエラーはメールに送られ、画面にもログにも出ない
- 対策：**`>> ファイル 2>&1` で標準エラーも必ずファイルに残す**

### 後片付け
- `crontab -e` → `j` → `dd` → `:wq` で失敗ジョブを削除
- 残したジョブ：
  ```
  */5 * * * * df -h / >> /home/kaito/df.log 2>&1
  ```
- 記録例（ディスク使用率 6%）
  ```
  /dev/mapper/almalinux-root   35G  2.0G   34G   6% /
  ```

## 面談で話す用まとめ
> cron で定期ジョブを登録し、出力ファイル・/var/log/cron・crontab の保存先の3点で動作を確認しました。
> あえて権限のないディレクトリに出力するジョブを作り、ログ上は CMD/CMDEND と正常終了に見えても、実際は Permission denied で一度も成功していないケースを確認しました。
> そのため、ジョブの出力はエラーも含めて `2>&1` でファイルに残す運用が必要だと理解しています。
